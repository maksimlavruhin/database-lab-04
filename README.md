# Лабораторная работа №4 · Группировка, представления и CTE

Настольное приложение для учёта экспериментов по ИИ-модерации текста. В этой версии доступны функции предыдущих лабораторных.

## Запуск

Скачайте или клонируйте репозиторий и откройте его папку в терминале.

Нужны Python 3.12, запущенный PostgreSQL версии 13 или выше и роль с правом создавать схемы в выбранной базе. Для чистого запуска подойдёт локальная база `postgres` или отдельная учебная база. Дистрибутивы для macOS, Windows и Linux доступны на [сайте PostgreSQL](https://www.postgresql.org/download/).

**macOS и Linux**

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m lab04
```

**Windows PowerShell**

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m lab04
```

В окне приложения введите адрес, порт, имя базы, имя роли PostgreSQL и пароль. Адрес `localhost` и порт `5432` подходят для локального PostgreSQL со стандартными настройками.

1. Нажмите **Подключиться**.
2. Нажмите **Создать схему и таблицы**.
3. Нажмите **Добавить демонстрационные данные**.
4. Откройте **Показать данные** и выберите инструмент работы.

Приложение использует схему `moderation_lab4`. При стандартной структуре создание схемы и загрузку примеров можно повторять. Меняйте структуру в выбранной лабораторной. Если переименуете базовые таблицы или поля, верните исходные имена для дальнейшего использования сводки и готовых форм ввода.

Конструкторы выводят до 1000 строк. Загруженные результаты можно сортировать по заголовкам столбцов и фильтровать по тексту. Пароль вводится при подключении. События и ошибки записываются в `database-labs.log`.

## Возможности

- [Конструктор SELECT](database_labs/query_forms.py) поддерживает ROLLUP, CUBE и произвольные GROUPING SETS.
- [Модуль отчётов](database_labs/report_forms.py) создаёт VIEW и MATERIALIZED VIEW из настроек SELECT, показывает структуру и данные, заменяет определение обычного VIEW, обновляет данные материализованного представления и удаляет оба вида. Конструктор CTE объединяет несколько блоков WITH.

## Что показать на защите

1. В SELECT выберите `experiments`, измерения `dataset_id` и `model_id`, агрегат COUNT без поля. Сравните ROLLUP и CUBE. В GROUPING SETS добавьте отдельно `dataset_id`, затем `model_id`, затем пустой набор для общей строки. Общий COUNT равен 6.
2. В модуле представлений создайте VIEW `good_runs` по таблице `experiments`, установив WHERE `f1 >= 0.80`. Откройте структуру и данные. Замените определение с теми же выходными столбцами и порогом `0.85`; останутся два запуска.
3. Создайте MATERIALIZED VIEW `runs_snapshot` на основе `experiments`. Через форму ввода добавьте эксперимент и откройте `runs_snapshot`. После команды **Обновить данные MATERIALIZED VIEW** в нём появится новая строка.
4. В конструкторе CTE добавьте блок `qualified` из `experiments` с `f1 >= 0.80`. Затем добавьте `large_runs` из CTE `qualified` с `samples >= 900`. Выберите `large_runs` для вывода. В исходных демоданных этому условию отвечают два запуска блога.
